# Answering a public verification challenge

**Status:** experimental tooling in AACP run protocol v0.3. Not a certification, a ranking
or a federation authority.

Projects sometimes publish an open invitation: *here is the key, the signed results and
the generator; recompute the hashes and try to break the Merkle root.* AACP can answer
that with a run whose every value is recomputable, and keep three things apart that a
quick reply tends to merge: what the producer's claims establish, what the runner observed
on its own initiative, and what nobody has established.

## What the lab records

| Record | Where | What it is |
|---|---|---|
| `challenge` | `SCOPE.json` | Link to the public request, who made it, what it asked (in the runner's words), and whether it asked for endorsement. Context only: never consent, an offer, admission or a publication approval. |
| `public_boundary` | `SCOPE.json` | The pinned file (repo, commit, path, SHA-256) where the producer documents its procedure, claims and limits. Admission is the runner's, not the producer's. |
| Claims | `results/claims.json` | The producer's documented properties, checked by the runner's own code: `ESTABLISHED`, `CONTRADICTED` or `NOT_ESTABLISHED` with unresolved obligations. |
| Probes | `results/probes.json` | Runner-authored observations, each with a class, a deterministic witness, source locators and the runner's assessment level. Never a claim result, never summed. |
| Draft reply | `.local/CHALLENGE-RESPONSE.md` | Generated by `respond` from the records above; outside the package manifest. |

Inputs that a check verifies a signature or digest over use `"format": "bytes"`, so the
check sees the exact published bytes rather than re-serialised JSON.

## Sequence

```sh
python -m conformance.lab init <run_id> --template templates/runs/<case>/SCOPE.json   # copies verifier/
python -m conformance.lab pin <run_id>                    # fetch, hash every file, verify the boundary
python -m conformance.lab freeze <run_id>                 # prints the plan hash: publish it first, then
python -m conformance.lab freeze <run_id> --published-ref <URL>   # or --not-preregistered (reported)
python -m conformance.lab run <run_id>
python -m conformance.lab package <run_id>
python -m conformance.lab respond <run_id> --drafted-by agent:<id> --ai-assisted \
    --scope-ref <where readers find SCOPE.json>
(cd runs/<run_id> && python3 rerun.py)                    # REPRODUCED, DIVERGED or NOT_REPRODUCIBLE
```

`share` and `publish` then deliver the package as a runner-attributed public-boundary
result (see [FEDERATION-TRACKS.md](FEDERATION-TRACKS.md#public-boundary-compatibility)).
Posting the draft reply, sharing and publishing are a person's decisions.

## Writing probes that hold up

- State the probed property neutrally, as something that could hold (*"S6 binds the leaf
  count"*), so `NOT_DEMONSTRATED` is a meaningful outcome.
- Put the numbers in the witness: digests, roots, key bytes, line numbers. A reader should
  be able to recompute every value without the runner's prose.
- Set `affects_pinned_artifact` honestly. A construction flaw shown only on constructed
  inputs is `false` even when it matters for the next release.
- Read producer code as data. A locator names the bytes that were read; nothing is
  executed.
- Label independence by what the runner knew. Reading the producer's verifier before
  writing your own makes the run `SECOND_IMPLEMENTATION`, however different the code.

## Worked example: NTI witness package

[`templates/runs/nti-witness/`](../templates/runs/nti-witness/) answers the challenge in
[aeoess/agent-governance-vocabulary#177](https://github.com/aeoess/agent-governance-vocabulary/issues/177#issuecomment-6706266993)
against `abisheakp197/Neutral-Trust-Infrastructure`. It pins two revisions of that
repository (the package and its first published version), checks the eight documented and
runner-authored claims with a standard-library RFC 8032 Ed25519 and three Merkle rules
(documented, RFC 6962 split, as implemented), and runs seven probes. The tests build a
synthetic package with test keys and run the same scope end to end
([tests/lab/test_nti_example.py](../tests/lab/test_nti_example.py)); they never use the
producer's bytes.
